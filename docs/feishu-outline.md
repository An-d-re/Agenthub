**Memory 示例**：

### 四、协作案例（2 页）

#### 案例 1：测试自动化的五次迭代（重点）

用时间线图示：

```
第1轮 ──→ 第2轮 ──→ 第3轮 ──→ 第4轮 ──→ 最终
CSS选择器   Zustand   任务数量   MCP断连   规则体系
失效       Store为空  判断错误   退化为脚本  建立
│          │          │          │          │
└─ 人发现  └─ 人发现  └─ 人发现  └─ 人发现  └─ Skill
  并指出    架构问题   竞态条件   并要求写   + Memory
  根因      并解释     并指出     入强制执行  永久生效
```                       

关键引用（从 `docs/ai-collaboration-record.md` 复制的原文片段，展示每次迭代的"根因→修复→沉淀"逻辑）。

**协作价值**：这个案例展示了人机协作不是"AI 写代码人看"，而是**错误驱动规则沉淀**——每一轮失败都产出一条永久规则，五轮下来形成了一个牢不可破的测试执行体系。

#### 案例 2：WebSocket 心跳空函数（简要）

```
AI 生成代码                人发现                    AI 修复
───────                   ─────                    ──────
_wait_pong():     →   函数体为空！         →   asyncio.Event
    pass              心跳形同虚设              + wait_for 重写
```

**启示**：AI 代码能通过语法检查，但语义可能完全空洞。人的审查重点是"这段代码真的做了它声称要做的事吗？"而非格式问题。

### 六、协作方法论（1 页）

5 条核心经验（从详细版提取，每条一句话）：

1. **CLAUDE.md 是最重要的投资** — 减少 80% 的"AI 跑偏"
2. **Memory 是纠错的持久化** — 单次纠正 → 永久生效
3. **AI 代码需要语义审查，不是语法审查** — 心跳空函数的教训
4. **Skill 写可执行指令，不是描述性文档** — 精确 > 模糊
5. **AI 会绕过限制，需要显式禁止** — MCP 断连退化为脚本的教训

# ADR 0001: 使用 huashu-design 作为前端重设计的原型工具

## 决策

使用 huashu-design skill 产出高保真 HTML 设计原型，确认视觉方向后，手动翻译为 Next.js + Tailwind + CSS 变量代码落地。

## 背景

当前前端基于 Apple HIG 设计系统（CSS 变量 + Tailwind + shadcn/ui），团队认为视觉上"能用但不够美观"。需要对以下视图进行统一重设计：

- 封面页、三栏主布局、聊天流、卡片系统（方案对比/任务 Pipeline/差异对比）、面板系统（Agent 编辑器/群聊编辑器/Trace 面板/DAG 编辑器）
- 新增：Agent 可视化办公室（独立全屏页 + 右侧栏迷你版）

## 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| **huashu-design 出原型 → 手写 React** | 自由度高、不受组件框架限制、视觉探索效率高 | 有翻译成本、需要逐组件对照落地 |
| 直接在 React 代码里改 | 无翻译损耗 | 受 Tailwind 心智模型限制、视觉探索空间小、改一轮成本高 |
| 用 frontend-design skill | 产出可部署的 React 代码 | 面向生产级 Web App，不适合纯视觉探索阶段 |

选择 huashu-design，因为当前阶段的核心需求是**视觉方向探索**，不是代码产出效率。

## 影响

- huashu-design 产出的 HTML/CSS 原型不是可部署代码，需要手动翻译为 React 组件
- 翻译阶段风险可控：当前 ~90% 视觉样式由 CSS 变量控制，原型定下的色彩/圆角/阴影等可通过修改变量值全局生效
- 新增的"办公室"视图需要在 Next.js 中新建路由和状态管理，不在纯视觉改动范围内

## 设计参考

- 腾讯 Marvis（马维斯）的"办公室"视图：Agent 拟人化、工位分布、实时状态动画
- Agent 协作动画方向：两个 Agent 协作时靠近聊天、传递材料时 A 走向 B

## 设计约束

- 必须支持浅色/暗色双主题
- 终端用户：开发者 + 产品经理 两类人群
- 保留 Apple 设计感但提升美观度，不一定要完全推翻
